# Publication invariants during refactoring

The website manifest and immutable upstream approval contracts remain the publication boundary. A structural change must preserve generated bytes, inventory fields, license/attribution, status vocabulary and rewritten immutable URLs at the approved locks. The synthetic output characterization test supplies an independent expected record; do not regenerate its expectations from production serialization.

Keep CLI flags and nonzero failures compatible. Collection requires explicit manifest, output, pydasc and dasc paths; validation takes manifest/docs; source updates distinguish unapproved candidates from malformed inputs. No operation executes upstream code or promotes a source implicitly.

Preserve adversarial coverage for duplicate keys, unapproved/dirty contracts, source identity, path and case aliases, symlink/hardlink/special files, bounded reads, Markdown/HTML resources, source immutability and output provenance. Fix known defects with separate regressions rather than freezing their behavior into fixtures.

Structural acceptance: full pytest, approved collection and output validation, authored physics checks, strict MkDocs build, built-site/accessibility checks, deterministic recollection, unchanged approved output bytes and actionlint. Changed rendering must be reviewed explicitly. These engineering checks do not certify physics claims, human accessibility or remote environment protections.
